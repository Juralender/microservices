# Сервис построения маршрутов и картографии

## Назначение и область применения

Сервис представляет собой легковесный фасад, скрывающий работу с одним или несколькими внешними картографическими сервисами
или поставщиками данных о дорожной обстановке. Он предоставляет всем внутренним потребителям
(приложениям для клиентов и водителей) единый стабильный интерфейс для получения маршрута и расчетного времени прибытия (ETA),
независимо от того, какой сторонний провайдер используется в конкретном регионе.

## Собственные данные

**Кэш маршрутов** (Redis): кэш с коротким временем жизни, хранящий результаты недавних запросов маршрутов и ETA (ключ: точка отправления + пункт назначения); 
служит для снижения затрат на внешние API и уменьшения задержек.

## Зоны ответственности

- Построение маршрута и расчет ETA с учетом дорожной обстановки от магазина до адреса клиента (для доставки).
- Построение маршрута и расчет ETA с учетом дорожной обстановки от местоположения клиента до магазина (для самовывоза).
- Абстрагирование и нормализация ответов от внешнего картографического провайдера, настроенного для конкретного региона.
- Кэширование недавних запросов для контроля расходов на сторонние API.

## Предоставляемый API (синхронный)

| Метод | Эндпоинт | Описание | Потребители |
|---|---|---|---|
| GET | `/directions/route?from={}&to={}` | Полилайн маршрута + ETA с учетом пробок | API Gateway (маршруты для самовывоза клиентом), сервис диспетчеризации доставки |

### Внешняя интеграция

| Цель | Вызов | Назначение |
|---|---|---|
| Картографический сервис / сервис данных о пробках (например, Google Maps / Mapbox / Yandex Maps) | routes/ETA/traffic | Непосредственный расчет маршрута |

## Нефункциональные характеристики

- **Абстракция от поставщика**: выбор внешнего провайдера определяется конфигурацией, а не кодом; это позволяет использовать другого картографического провайдера при выходе на рынок новой страны без внесения изменений в сервисы-потребители.
- **Контроль затрат**: сочетание кэширования и абстракции от провайдера позволяет компании вести переговоры или менять поставщиков по мере роста объема запросов до миллионов (как предусмотрено в сценарии Kata).
